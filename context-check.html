Контекст, з яким можна продовжити роботу

Уяви, що завтра відкриваєш нову розмову з AI. Як пояснити, що вже працює, що плануємо змінити та чого не можна чіпати? Зараз зберемо такий запис на невеликому навчальному проєкті й перевіримо, чи можна за ним продовжити роботу.

Пройди десять кроків по черзі. Наприкінці у твоїй копії пакета будуть два власні файли: docs/practice/02-context.md і docs/practice/handoff.md. Нову можливість дашборда тут ще не реалізуємо. Усі команди, промпти й короткі пояснення є на цій сторінці; інший навчальний репозиторій не потрібен.

Позначки нижче допомагають пам’ятати місце зупинки. Сторінка не бачить твого термінала, файлів чи розмови з AI та не перевіряє виконання команд. Вона не просить контакти й не надсилає дані назовні. На публічній вебсторінці GitHub обробляє звичайні дані відвідування.

Без автоматичного збереження. Можна завантажити чекліст перед закриттям сторінки.

Позначено: 0 із 10

1. Відкрий навчальний пакет

Що робити. Увійди у свій GitHub-акаунт і відкрий приватний пакет мінікурсу. Натисни Code → Download ZIP, дочекайся завантаження й розпакуй архів. На Windows вибери Extract All / Видобути все, на macOS відкрий архів подвійним натисканням. Працюємо з розпакованою текою. Початковий ZIP залиш для порівняння наприкінці уроку.

Якщо бачиш відмову в доступі чи 404, постав відео на паузу. Перевір акаунт і прийняте запрошення, потім звернися до команди курсу. Не змінюй видимість репозиторію та не шукай заміну в іншому пакеті. Публічний чекліст не надає доступу до приватного коду.

Замість ZIP: HTTPS-копія, якщо вже користуєшся Git

У терміналі перейди у свою теку для навчальних проєктів і виконай дві команди. Це альтернатива ZIP. Якщо Git просить авторизацію, використовуй свій налаштований GitHub-вхід; токени в документи чи промпти не вставляй. Наявну теку з такою назвою не перезаписуй.

git clone https://github.com/genkovich/agentic-engineering-mini-kit.git
cd agentic-engineering-mini-kit

У розпакованій теці знайди package.json. Назва теки може закінчуватися на -main; орієнтуйся на файли всередині. У VS Code вибери File → Open Folder / Файл → Відкрити теку й відкрий саме цю теку. Можеш користуватися своїм редактором. Потім відкрий Terminal → New Terminal / Термінал → Новий термінал і введи команди нижче по одній, після кожної натискаючи Enter.

node --version
npm --version

Для курсу потрібен Node.js 22 або 24: перша команда має показати v22. чи v24. на початку версії, друга номер npm. Якщо команда не знайдена, відкрий офіційне завантаження Node.js, вибери 22 або 24 та інсталятор своєї ОС. Після встановлення відкрий новий термінал і перевір версії повторно. Поки це не працює, далі не переходь. Агента відкриємо у кроці 4; SDD й плагіни зараз не потрібні.

Що має бути видно. Поряд лежать package.json, server.js, теки lib/, views/, fixtures/ і templates/. Команди показують версії інструментів.

2. Подивися на перевірки до змін

Що робити. У терміналі біля package.json встанови залежності з файлу фіксації версій. Це потребує інтернету.

npm ci

Дочекайся завершення: термінал знову запропонує ввести команду. Кількість встановлених пакетів може відрізнятися від екрана лектора. Якщо є помилка, збережи її текст і постав відео на паузу. При ENOENT із згадкою package.json перевір, чи термінал відкрито в корені пакета. До перевірок переходь після успішного встановлення.

npm run verify

Що має бути видно. У незміненому скелеті очікуємо два тести без помилок: перевірку health-відповіді та HTML-оболонки з CSP. Вони ще не перевіряють список сесій, бо його немає. Перед тестами preverify вирівнює дати навчальних фікстур.

Збережи фактичний підсумок свого запуску: команду, кількість тестів і результат. Пізніше перенесеш його у власну нотатку. Очікування на цій сторінці та приклади лектора не є виводом твого термінала.

Орієнтир для читання підсумку наведено нижче. Це приклад очікування, не результат твого запуску; оформлення рядків може відрізнятися.

tests 2
pass 2
fail 0

3. Відкрий те, що працює зараз

Що робити. Запусти навчальний дашборд командою нижче. Дочекайся повідомлення з адресою http://127.0.0.1:4180, скопіюй її в адресний рядок браузера й відкрий. Залиш цей термінал працювати. Він зайнятий сервером, тому не показує нового запрошення вводу; це очікувано. Для подальших команд вибери Terminal → New Terminal у тій самій теці.

npm run demo

Що має бути видно. На сторінці є напис No slice is wired up yet. Це очікуваний порожній екран. У фікстурах лежать шість файлів сесій у трьох проєктах, але код ще не збирає їх у список. Тому шість файлів на диску та нуль показаних сесій не суперечать одне одному.

npm run demo через scripts/demo.mjs явно задає навчальну fixtures/claude-home і порт 4180, навіть якщо в терміналі раніше були інші значення. Перед запуском predemo вирівнює дати фікстур. Для цієї практики не запускай npm start на особистих логах і не підключай ~/.claude. Коли завершиш роботу з дашбордом, зупини його через Ctrl+C.

Якщо відповідь нечітка: Zero-shot, One-shot і Few-shot

Усі варіанти нижче стосуються однієї задачі: відділити готове від запланованого. Спочатку відкрий server.js, маршрут GET /: він показує порожню сторінку. Потім знайди S1 у docs/roadmap.md: список сесій там поки запланований.

Zero-shot означає запит без прикладу готової відповіді: «Прочитай ці файли й запиши висновки у форматі “твердження | стан | джерело”. Невідоме познач окремо. Файли не змінюй».

Додай зразок «GET / показує порожню сторінку | є зараз | server.js». Це One-shot, один приклад. Якщо додати ще «Список сесій, новіші першими | заплановано | docs/roadmap.md, S1», отримаємо Few-shot, кілька прикладів.

Shot тут означає зразок виконання задачі в запиті. Це не перенавчання моделі й не кількість повідомлень. Вибери один варіант; надсилати всі по черзі не потрібно. Якщо початкова відповідь уже зрозуміла, пропусти уточнення. Нові висновки однаково перевір за файлами.

Що має бути видно. Конкретне зауваження можна перевірити в названому файлі. Якщо агент пише «список уже читається через реєстр», відкрий відповідні функції та виправ цю помилку в нотатці. Якщо зауважень немає, перевір названий обсяг; вигадувати дефект для виконання кроку не потрібно.

Такий поділ на менші дії називають декомпозицією. Для цієї перевірки кроки залишаємо в одному запиті. У довшій роботі їх можна надсилати окремо й перевіряти результат перед продовженням. Chain-of-thought стосується проміжних кроків міркування; наша перевірка за файлами не демонструє внутрішніх міркувань моделі.

10. Перевір, що залишилося після уроку

Що робити. Ще раз запусти перевірки та переглянь зміни. Порівняй реальний підсумок із початком роботи й допиши його у власний контекст. Нових runtime-файлів або змін тестів для завершення цього уроку не потрібно.

npm run verify
git status --short
git diff

Звичайний git diff не показує вміст нових невідстежуваних файлів. Відкрий власні docs/practice/02-context.md і docs/practice/handoff.md у редакторі та перевір їх окремо. Якщо працюєш із ZIP без Git-історії, пропусти дві git-команди й скористайся порівнянням нижче.

Перевірити ZIP-копію без Git

Розпакуй збережений початковий ZIP ще раз в окрему теку поза робочим пакетом. Це має бути та сама версія пакета, з якої починалася практика; нове завантаження могло вже змінитися. Початкову копію не редагуй. У ній також знайди корінь із package.json.

У терміналі своєї робочої копії виконай команду нижче. Заміни текст усередині лапок на повний шлях до кореня недоторканої копії: скористайся «Копіювати шлях» у файловому менеджері або перетягни теку в термінал. Перевір, що весь шлях із пробілами обрамлений однією парою подвійних лапок, без подвійного екранування.

node scripts/compare-kit.mjs "<path to unpacked untouched kit>"

Команда нічого не змінює. Вона порівнює байти й показує всі ADDED, CHANGED та REMOVED, ігноруючи лише теки node_modules, .git та службові файли .DS_Store, Thumbs.db. Дати файлів не впливають на результат, правила в .claude/ перевіряються. Символічні посилання або помилка читання зупиняють перевірку.

Після цього уроку очікуємо лише два ADDED: твої docs/practice/02-context.md і docs/practice/handoff.md. Це очікування; збережи власний фактичний список. Код завершення 1 означає знайдені відмінності, 0 означає їх відсутність, 2 означає помилку перевірки. Інші зміни спочатку розбери. Позначки вебчекліста не є результатом цього порівняння.

Що має бути видно. У скелеті залишилися два наявні тести; вони проходять. Твої зміни стосуються лише запланованих документів. У нотатках є власний контекст, handoff і фактичний результат перевірки свіжою сесією. Якщо її ще не вдалося запустити, явно познач це: відповідна частина вправи ще не завершена. Секретів та особистих логів немає. Реалізація S1 почнеться пізніше, в уроках 3–4.

Коміт необов’язковий. Якщо користуєшся Git і хочеш його зробити, спочатку переглянь та додай лише свої два файли; перевір підготовлений diff. Не додавай усі файли наосліп і не виконуй force-операцій.

git add docs/practice/02-context.md docs/practice/handoff.md
git diff --cached
git commit -m "docs: prepare lesson 2 context and handoff"
