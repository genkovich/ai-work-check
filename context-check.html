Мінікурс · урок 2

Context Engineering: перевіряємо контекст проєкту

Агенту потрібні точні інструкції й зрозумілий опис проєкту. На готовому застосунку перевіримо основні та вкладені правила, створимо карту через survey і подивимося, чи нова сесія правильно розбереться в роботі.

Основні файли вже підготовлені. Єдиний обовʼязковий новий документ у проєкті: docs/architecture-map.md. Власні результати запишеш у поля цієї сторінки й експортуєш одним файлом. Реалізацію ще не починаємо.

Маршрут оновлено: старі позначки попередньої вправи не переносяться, бо кроки тепер інші.

Позначки нижче допомагають пам’ятати місце зупинки. Сторінка не бачить твого термінала, файлів чи розмови з AI та не перевіряє виконання команд. Вона не просить контакти й не надсилає дані назовні. На публічній вебсторінці GitHub обробляє звичайні дані відвідування.

Без автоматичного збереження. Можна завантажити чекліст перед закриттям сторінки.

Позначено: 0 із 10

1. Завантаж і відкрий проєкт

Що робити.

Увійди у GitHub і відкрий пакет курсу. Для 404 перевір акаунт і прийняте запрошення; звернися до команди курсу, якщо доступу немає. Публічний чекліст не надає доступу до коду.

Потрібні Git, Node.js 22 або 24 і редактор, наприклад VS Code. Відкрий термінал у своїй теці навчальних проєктів поза іншими Git-репозиторіями. Скопіюй кіт:

git clone https://github.com/genkovich/agentic-engineering-mini-kit.git
cd agentic-engineering-mini-kit

Не перезаписуй наявну теку. При авторизації користуйся своїм GitHub-входом, не вставляй токени в промпти.

Альтернатива: Code → Download ZIP, потім розпакуй архів. На Windows це Extract All / Видобути все. У редакторі вибери File → Open Folder, відкрий теку з package.json, потім Terminal → New Terminal.

node --version
npm --version
git --version

Після встановлення інструментів відкрий новий термінал. При відсутній команді не переходь далі.

Що має бути видно. У редакторі є package.json і server.js. Node показує v22. або v24.; npm і Git показують свої версії.

2. Перевір і запусти застосунок

Що робити.

Встанови залежності у звичайному терміналі:

npm ci

Дочекайся завершення: термінал знову запропонує ввід. При ENOENT зі згадкою package.json перевір теку. Інші помилки спочатку прочитай і виправ; відео можна поставити на паузу.

npm run verify

Це два тести скелета: health-відповідь і HTML-оболонка. Приклад очікування, не результат твого запуску:

tests 2
pass 2
fail 0

Збережи фактичний підсумок у звичайних нотатках або історії термінала. Окремий документ за шаблоном для цього не потрібен.

У терміналі запусти:

npm run demo

Дочекайся адреси http://127.0.0.1:4180, відкрий її в браузері. Термінал зайнятий сервером. Для наступних команд вибери Terminal → New Terminal у тій самій теці. Зупинка сервера: Ctrl+C.

На диску є шість файлів сесій у трьох проєктах, але застосунок ще не збирає список. Вкладені subagents/ та tool-results/ сесіями нашого переліку не вважаємо. Фікстури означають штучні навчальні дані; особисті розмови тут не потрібні.

scripts/demo.mjs явно задає фікстури й порт 4180; predemo вирівнює їхні дати. Не запускай npm start і не підключай ~/.claude. За бажанням відкрий http://127.0.0.1:4180/api/health: claudeHome має вказувати на fixtures/claude-home. При EADDRINUSE зупини власний попередній сервер; невідомі процеси не чіпай.

Що має бути видно. Два стартові тести проходять; на 127.0.0.1:4180 видно No slice is wired up yet. Health вказує на fixtures/claude-home.

3. Підготуй Git, агента й SDD

Що робити.

Після clone перевір корінь. Він має бути саме текою пакета, а не батьківським проєктом:

git rev-parse --show-toplevel
git status --short

Після ZIP спочатку виконай git init саме в розпакованій теці з package.json, потім перевір корінь командами вище. Якщо корінь не збігається, не запускай SDD: перенеси копію поза інший репозиторій.

Для обох способів перевір автора комітів:

git config user.name
git config user.email

Якщо значень немає, задай їх локально. Заміни текст у лапках своїм імʼям та дозволеною для комітів адресою (можна власною GitHub noreply):

git config user.name "YOUR NAME"
git config user.email "YOUR COMMIT EMAIL"

Лише після ZIP: переглянь git status --short, переконайся, що це тільки навчальні файли без секретів, і зроби початковий коміт:

git add .
git diff --cached --stat
git commit -m "Start mini-course practice"

Clone вже має початкову історію; ці команди йому не потрібні. Відкрий .claude/sdd.local.example.md у редакторі й через File → Save As збережи копію як .claude/sdd.local.md. Наявні власні налаштування не перезаписуй. Цей локальний файл уже виключено з Git.

git rev-parse HEAD

Збережи повний хеш поза пакетом. У фінальних командах він замінить BASE_COMMIT. Survey робить коміт, тому лише звичайного diff наприкінці буде недостатньо.

Claude Code: основний показ у відео

У звичайному терміналі перевір:

claude --version

Якщо команда відсутня, вибери інсталятор своєї ОС з офіційного Quickstart. Він завантажує і запускає програму; перевір адресу.

macOS, Linux або WSL:

curl -fsSL https://claude.ai/install.sh | bash

Windows, саме PowerShell:

irm https://claude.ai/install.ps1 | iex

Відкрий новий термінал і повтори claude --version. За потреби є діагностика встановлення. Встановлена програма ще потребує акаунта з доступом до Claude Code. Виклики агента оплачуються за твоїм тарифом; сам дашборд і тести модель не викликають.

claude

Під час першого запуску пройди вхід за підказками. Повторний вхід: /login усередині Claude Code. Перевір показану теку проєкту. Тепер усередині Claude Code вводь команди по одній:

/plugin marketplace add genkovich/sdd
/plugin install sdd@sdd
/reload-plugins

SDD додає готові інструкції для роботи з проєктом. Відкрий список через / і знайди /sdd:survey. Якщо команда відсутня, перевір повідомлення встановлення, перезавантаж плагіни або перезапусти Claude Code. Репозиторій SDD містить інструкції.

Якщо працюєш у Codex або Cursor

Встановлюй SDD лише для свого інструмента. На Windows наступний скрипт запускай у Git Bash або WSL, не в PowerShell. Він завантажує й виконує код; перевір адресу.

Codex CLI: відкрий корінь пакета, перевір codex --version. За потреби є офіційний запуск. У звичайному терміналі виконай:

curl -fsSL https://raw.githubusercontent.com/genkovich/sdd/main/install.sh | bash -s -- codex

Перезапусти Codex у цьому проєкті. Команда карти у розмові: $sdd-survey. Не встановлюй одночасно marketplace-варіант SDD: він має інші назви команд.

Cursor: відкрий цю саму теку й у звичайному терміналі виконай:

curl -fsSL https://raw.githubusercontent.com/genkovich/sdd/main/install.sh | bash -s -- cursor

Перезапусти Cursor або виконай Developer: Reload Window. У чаті введи / та вибери sdd-survey.

Для Codex скрипт додає .agents/skills/ і .codex/agents/, для Cursor .cursor/skills/ і .cursor/agents/. Це очікувані файли встановлення; код застосунку вони не реалізують.

Що має бути видно. Корінь Git збігається з текою пакета. Початковий хеш збережено, локальні налаштування є, survey доступний у вибраному агенті.

Явне читання не доводить автоматичного завантаження інструкцій.

Що має бути видно. Агент пояснює стартовий застосунок і вказує, де лежать спеціальні інструкції. Ти можеш знайти ці місця у файлі.

Що має бути видно. Є docs/architecture-map.md з описом поточного застосунку й посиланнями на код. Нову фічу не реалізовано.

6. Перевір карту за кодом

Що робити.

Відкрий карту та файли, названі в запиті нижче. Нам потрібні перевірні твердження: які маршрути вже працюють, де формується HTML, як запускати тести.

Звір docs/architecture-map.md з server.js, lib/claude/index.js,
lib/sources.js, views/layout.js, scripts/demo.mjs і test/skeleton.test.js.
Спочатку прочитай джерела, потім порівняй твердження, далі запропонуй правки.
Для кожного зауваження назви файл і функцію.
Відділи поточний код від планів та коментарів.
Нічого не змінюй без мого погодження. Особисті логи не відкривай.

У server.js є прямий імпорт claudeHome з адаптера, хоча коментар lib/sources.js каже про відсутність таких імпортів. У lib/claude/index.js ще немає функції читання списку. Карта має описувати фактичний код.

Для нечіткої відповіді попроси формат «твердження | стан | джерело». Без зразка це Zero-shot. Один приклад «GET / показує порожню сторінку | є зараз | server.js» дає One-shot. Додай «Список сесій | бажана зміна | README.md» і матимеш Few-shot. Джерела прикладів уже відкриті; це не перенавчання моделі.

Поділ «прочитай → порівняй → запропонуй правки» називається декомпозицією. Chain-of-thought стосується проміжних кроків міркування. Тут ми звіряємо джерела й висновок; внутрішніх міркувань моделі не бачимо.

Погодь лише підтверджені виправлення карти. Якщо помилки немає, вигадувати її для проходження не потрібно.

Що має бути видно. Твердження карти підтверджуються кодом; заплановані можливості не описані як готові.

7. Знайди вкладені інструкції

Що робити.

Відкрий views/AGENTS.md, views/CLAUDE.md і views/layout.js. Спеціальні HTML-правила лежать у вкладеній теці поруч із кодом. Короткий CLAUDE-файл імпортує той самий зміст через @AGENTS.md.

Готуємо майбутню зміну сторінки, але код зараз не пишемо.
Прочитай views/layout.js та відповідні інструкції проєкту.
Які готові функції треба використати для сторінки й текстових значень?
Що потрібно зберегти в політиці безпеки HTML?
Назви файл-джерело кожного правила. Якщо вкладені інструкції
не потрапили в контекст, відкрий views/AGENTS.md явно й зазнач це.

layout() створює оболонку сторінки. esc() готує текстові значення для вставлення у HTML. Натомість параметр body уже очікує готовий HTML. Content-Security-Policy обмежує дозволені ресурси сторінки; її не послаблюємо без погодження.

Claude Code завантажує вкладені інструкції при читанні відповідних файлів. Codex на початку збирає AGENTS від кореня до робочої теки: при запуску з кореня не припускай, що вкладений файл уже включений. Кореневий AGENTS тому прямо вимагає прочитати його перед роботою у views. Явне читання теж корисне; просто познач його чесно.

Що має бути видно. У відповіді є layout(), esc(), CSP і views/AGENTS.md як джерело. Ти звіряєш це з поточним layout.js.

8. Перевір правила для даних

Що робити.

Відкрий docs/rules/session-data.md. Тут єдина політика даних: навчальні фікстури, метадані замість текстів розмов, основні файли сесій і заборона запису застосунку в джерело.

Поруч відкрий адаптер свого інструмента. Для Claude Code це .claude/rules/session-index.md з paths: ["lib/claude/**/*.js"] та імпортом @../../docs/rules/session-data.md. Для Cursor це .cursor/rules/session-data.mdc із тим самим globs, alwaysApply: false та посиланням @docs/rules/session-data.md.

Готуємо майбутній список сесій. Зараз нічого не реалізуй.
Прочитай lib/claude/index.js і правила для даних, на які вказує AGENTS.md.
Назви дозволене джерело даних, межі читання та записи, які слід пропустити.
Поясни, як правило повʼязане з lib/claude/index.js і views/layout.js.
Посилайся на docs/rules/session-data.md. Не стверджуй, що текст правила
технічно забороняє доступ або вже доводить безпеку реалізації.

Шаблон охоплює lib/claude/index.js, але не views/layout.js. Політика стосується будь-якої роботи з даними; шаблон лише допомагає інструменту підключити її у відповідному місці.

У Claude scoped rule завантажується при читанні відповідного файла. У Cursor правило з globs додається, коли відповідний файл є в контексті. Codex не покладається на ці адаптери: кореневий AGENTS прямо посилається на політику. Якщо автоматичного включення не видно, прочитай файл явно й запиши це.

Документація: Claude Code, Codex AGENTS, Cursor rules. Текстові правила не замінюють технічних прав доступу.

Що має бути видно. Агент називає канонічну політику та правильно пояснює джерело даних, межі й шаблон шляхів.

9. Перевір нову сесію

Що робити.

Збережи карту та заверши поточну розмову. Claude Code: введи /exit, потім claude у звичайному терміналі тієї самої теки без resume або continue. Codex: введи /new. Cursor: створи новий чат у тому самому проєкті, не переносячи стару розмову.

Це нова сесія в навчальному проєкті. Потрібно підготувати роботу
над списком сесій і його сторінкою, але нічого не змінювати.
Знайди наявні інструкції та карту проєкту.
Поясни: що працює зараз, чого ще немає, що слід використати для HTML,
які дані можна читати та чого не можна робити з джерелом.
Назви файли й функції, які підтверджують відповідь.
Окремо зазнач, що довелося прочитати явно і що залишилося неперевіреним.
Не вигадуй результатів команд і не використовуй попередню розмову.

Перевір, чи агент знайшов правильні файли та не приписав застосунку готовий список. Звір пояснення HTML і даних. Запиши нижче, які інструкції довелося відкрити явно. Правильна відповідь сама по собі не доводить автоматичного підключення.

Якщо нову сесію ще не запускали, залиш крок 9 незавершеним. Допомога колеги або ручне читання корисні, але не замінюють цього запуску.

Що має бути видно. Нова сесія відновлює контекст за файлами. Є конкретна відповідь, яку можна звірити з кодом і правилами.

10. Переглянь зміни й збережи результат

Що робити.

У звичайному терміналі повтори:

npm run verify

У командах нижче заміни BASE_COMMIT своїм повним хешем із кроку 3:

git log --oneline BASE_COMMIT..HEAD
git diff BASE_COMMIT HEAD
git diff HEAD
git status --short

Команди показують коміти, закомічені й незакомічені зміни. Нові невідстежувані файли видно через status; відкрий їх окремо. Survey міг уже закомітити карту, тому порожній diff сам по собі не означає, що змін не було.

Очікуємо карту й службові файли обраного встановлення SDD. Код, тести й залежності залишаються початковими. Уточнення готових інструкцій допустимі лише після твоєї перевірки та погодження; обовʼязкових правок заради вправи немає.

Заповни поля під кроками: інструмент, фактичні запуски, перевірка нової сесії та неперевірене. Натисни Зберегти результат текстом до закриття сторінки. Поля не зберігаються автоматично, навіть якщо ввімкнено збереження позначок. Не вставляй секрети й приватні розмови.

У проєкті потрібна лише карта від survey. Окремі interview, бриф, roadmap і handoff для другого уроку не створюємо.

Що має бути видно. Два тести проходять, зміни зрозумілі, карта перевірена, власний результат нової сесії записано й експортовано.

Твій результат перевірки

Запиши коротко, що реально відбулося. Кожне поле вміщує до 3000 символів. Ці записи залишаються лише у відкритій вкладці до експорту; збереження позначок їх не зберігає. Не вставляй секрети або приватні розмови.

Натисни «Зберегти результат текстом» угорі сторінки. Експорт містить твої записи й позначки, але сам по собі не засвідчує виконання команд.

Цю сторінку можна зберегти як context-check.html і відкрити локально. Їй не потрібні сервер чи інтернет для читання, позначок і експорту. Доступ до пакета, встановлення залежностей та розмова з агентом мають власні вимоги й виконуються окремо. Не розраховуй на перенесення збережених позначок між браузерами, пристроями або локальною й вебкопією сторінки.
