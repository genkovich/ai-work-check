# Як я працюю з AI

Дві анкети мінікурсу з Agentic Engineering. Кожна це один HTML без залежностей.

- [Стартова: 10 запитань](https://genkovich.github.io/ai-work-check/), урок 1. Запитання про практики роботи з AI, яких курс і вчить, тому низький результат на старті очікуваний. Під кожним коротка підказка на прикладі застосунку зі списком покупок.
- [Фінальна: 45 запитань](https://genkovich.github.io/ai-work-check/final.html), необовʼязковий матеріал уроку 6. Пʼятнадцять тем по три запитання: вісім для інженера, сім для того, хто веде команду; блок команди можна пропустити. Версія: `mini-audit-final-v3`.

Стартові запитання йдуть по ланцюгу курсу: Intent, Context, Spec, Plan, Implementation, Verification, Learning; фінальні по пʼятнадцяти темах у двох ролях. Бали описують відповіді за самооцінкою, не професійний рівень. Назви «сильні» й «слабкі» є умовними підказками всередині однієї анкети. Один навчальний випадок ще не підтверджує регулярної звички.

Проходити всі 45 запитань для завершення мінікурсу не потрібно.

Відповіді обробляються у браузері й не надсилаються автору. Немає реєстрації, аналітики чи автоматичного збереження. Результат можна завантажити текстом або як `result.json` (старт) чи `result-final.json` (фінал).

## Як це зібрано

`index.html` це єдине джерело стилів, рушія і обох наборів запитань; сторінка обирає набір за `data-mode` на `<html>`. `final.html` збирається з нього, а копії для пакета учасника лежать в іншому репозиторії:

```sh
node build.mjs                                        # index.html → final.html
node build.mjs --kit ../agentic-engineering-mini-kit  # плюс first-step.html, final-step.html, шаблони й тест пакета
```

Текстові версії `questionnaire.md` і `final-questionnaire.md` правляться рукою; тести перевіряють, що запитання в них ті самі, що в HTML.

## Перевірка

```sh
node --test test/first-step.check.mjs
```

GitHub Pages публікує корінь гілки `main`; `.nojekyll` вимикає обробку Jekyll. Опис репозиторію на GitHub оновлюється командою `gh repo edit --description '<опис>'`.

## Практика другого уроку

[Context Engineering: перевіряємо контекст проєкту](https://genkovich.github.io/ai-work-check/context-check.html): десять кроків із командами й підказками. Читаємо готові основні та вкладені інструкції, створюємо карту через survey і перевіряємо нову сесію агента. Єдина політика даних має короткі адаптери Claude Code та Cursor; для Codex передбачено явне читання через основні інструкції. Матеріали для роботи лежать у приватному кіті курсу; ця сторінка не надає доступу до нього й не публікує весь курс.

`context-check.html` працює самостійно, без залежностей або API. Зберігати десять позначок у браузері можна лише за власним вибором. Чотири поля дозволяють записати свій інструмент, фактичні запуски, результат нової сесії та неперевірене. Ці тексти залишаються у відкритій вкладці й не зберігаються автоматично, навіть коли ввімкнено збереження позначок. До закриття сторінки завантаж `lesson-2-context-result.md`: він містить позначки й власні записи, але не є автоматичним доказом виконання команд. Дані полів не надсилаються автору; секрети й приватні розмови сюди не вставляй. Старі позначки попередньої вправи не переносяться, бо маршрут змінився.

Перевірка сторінки: `node --test test/context-check.check.mjs`. Звірка посилань на файли та тверджень про код додатково виконується в приватному кіті: `node --test test/context-check.check.js`.
